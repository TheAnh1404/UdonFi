# 13 - Financial Specification

This document defines the core accounting framework, financial definitions, and transaction journal entries of the UdonFi V2 protocol.

## 1. Core Accounting Concepts

*   **Assets ($A$)**: All economic resources controlled by the smart contracts. This includes the total physical underlying tokens held in pool reserves (pool liquidity) plus the aggregate debt owed by borrowers.
*   **Liabilities ($L$)**: The claims of depositors on the protocol's assets. This represents the total value of supplied capital (compounded with interest) redeemable by holders of aTokens.
*   **Equity ($E$)**: The protocol's retained earnings and accumulated reserves, including collected reserve fees (stored in the Treasury reserve) and the Insurance Fund.
*   **User Supplied Assets**: The total underlying tokens deposited by suppliers, tracked on-chain via yield-bearing `aTokens`.
*   **User Debt**: The total underlying tokens owed by borrowers, tracked on-chain via `debtTokens`.
*   **Pool Liquidity**: The active cash balance (idle tokens) residing in the protocol contract reserves available for withdrawals or borrows.
*   **Treasury Reserve**: Accumulated protocol revenue collected via the Reserve Factor. Controlled by the Governance Board.
*   **Protocol Revenue**: The portion of borrow interest collected by the treasury, derived as $\text{Interest Paid} \times \text{Reserve Factor}$.
*   **Insurance Fund**: A dedicated buffer pool funded by protocol fees to cover bad debt during extreme liquidation cascades.
*   **Bad Debt**: Uncollateralized debt that occurs when a borrower's Health Factor drops below 1.0, and the value of their collateral is less than their outstanding borrow balance.
*   **Accrued Interest**: Compound interest generated by borrowers and added to global indexes on every block.

---

## 2. Protocol-Level Accounting Equation

The UdonFi V2 protocol enforces the balance sheet identity at the system level:

$$\text{Total Assets} = \text{Total Liabilities} + \text{Protocol Equity}$$

For any asset reserve $i$:

$$\text{Liquidity}_i + \text{Total Debt}_i = \text{Total Supplied}_i + \text{Treasury Reserve}_i + \text{Insurance Fund}_i$$

*   **$\text{Total Assets}_i$**: $\text{Liquidity}_i + \text{Total Debt}_i$ (cash in pool + active loans).
*   **$\text{Total Liabilities}_i$**: $\text{Total Supplied}_i$ (total redeemable claims by depositors).
*   **$\text{Protocol Equity}_i$**: $\text{Treasury Reserve}_i + \text{Insurance Fund}_i$ (retained earnings).

## 3. Transaction Accounting Rules

The following rules define the double-entry accounting ledger modifications for all protocol transactions.

### A. Deposit (Supply)
*   **Precondition**:
    - Reserve asset $i$ is active.
    - $\text{Total Supplied}_i + \Delta \text{amount} \le \text{supplyCap}_i$.
*   **State Transition**:
    - Underlying tokens are transferred from User wallet to Pool contract.
    - Scaled aTokens are minted to the User.
*   **Accounting Entries**:
    - **Debit**: Pool Liquidity ($+ \Delta \text{amount}$) [Asset]
    - **Credit**: User Supply ($+ \Delta \text{amount}$) [Liability]
*   **Events Emitted**: `Supply(user, asset, amount)`
*   **Post-execution Invariants**:
    - $\text{Total Supplied}_i \le \text{supplyCap}_i$
    - $HF_{user} \ge 1.0$ (if borrower)

### B. Withdraw
*   **Precondition**:
    - User has active supply balance.
    - Withdrawal amount $\le \text{actualSupply}_{user}$.
    - Post-withdrawal Health Factor $HF_{user} \ge 1.0$ (if user has active loans).
*   **State Transition**:
    - aTokens are burned from the User.
    - Underlying tokens are transferred from Pool contract to User wallet.
*   **Accounting Entries**:
    - **Debit**: User Supply ($- \Delta \text{amount}$) [Liability]
    - **Credit**: Pool Liquidity ($- \Delta \text{amount}$) [Asset]
*   **Events Emitted**: `Withdraw(user, asset, amount)`
*   **Post-execution Invariants**:
    - $HF_{user} \ge 1.0$

### C. Borrow
*   **Precondition**:
    - Reserve asset $j$ is active.
    - $\text{totalBorrowed}_j + \Delta \text{amount} \le \text{borrowCap}_j$.
    - Post-borrow Health Factor $HF_{user} \ge 1.0$.
*   **State Transition**:
    - Underlying tokens are transferred from Pool contract to User wallet.
    - Scaled debtTokens are minted to the User.
*   **Accounting Entries**:
    - **Debit**: User Debt ($+ \Delta \text{amount}$) [Asset]
    - **Credit**: Pool Liquidity ($- \Delta \text{amount}$) [Asset]
    - *(Note: Total Assets remains unchanged as physical cash is replaced by a loan asset)*.
*   **Events Emitted**: `Borrow(user, asset, amount)`
*   **Post-execution Invariants**:
    - $\text{Total Borrowed}_j \le \text{borrowCap}_j$
    - $HF_{user} \ge 1.0$

### D. Repay
*   **Precondition**:
    - User has active debt balance.
    - Repayment amount $\le \text{actualDebt}_{user}$.
*   **State Transition**:
    - Underlying tokens are transferred from User wallet to Pool contract.
    - debtTokens are burned from the User.
*   **Accounting Entries**:
    - **Debit**: Pool Liquidity ($+ \Delta \text{amount}$) [Asset]
    - **Credit**: User Debt ($- \Delta \text{amount}$) [Asset]
*   **Events Emitted**: `Repay(user, asset, amount)`
*   **Post-execution Invariants**:
    - $HF_{user} \ge HF_{pre}$

### E. Liquidation Settle
*   **Precondition**:
    - Borrower's Health Factor $HF_{borrower} < 1.0$.
    - Session ID locked successfully during the `prepare_liquidation` phase.
*   **State Transition**:
    - Liquidator transfers outstanding debt repayment to Pool contract.
    - Pool transfers seized collateral plus liquidation bonus to Liquidator.
    - Borrower's debtTokens and aTokens are burned.
*   **Accounting Entries**:
    - **Debit**: Pool Liquidity (debt asset, $+ \Delta \text{debt}$) [Asset]
    - **Credit**: Borrower Debt (debt asset, $- \Delta \text{debt}$) [Asset]
    - **Debit**: Borrower Supply (collateral asset, $- \Delta \text{collateral}$) [Liability]
    - **Credit**: Pool Liquidity (collateral asset, $- \Delta \text{collateral}$) [Asset]
*   **Events Emitted**: `LiquidationSeize(liquidator, borrower, session_id, repaid, seized)`
*   **Post-execution Invariants**:
    - $HF_{borrower} > HF_{pre}$ (closer to or above 1.0).

### F. Interest Accrual
*   **Precondition**:
    - $\Delta L = \text{currentLedger} - \text{lastAccrualLedger} > 0$.
*   **State Transition**:
    - Accumulator indexes (`borrowIndex`, `supplyIndex`) are updated.
    - User actual balances compound automatically based on new index.
*   **Accounting Entries**:
    - **Debit**: User Debt ($+ \text{Interest Accrued}$) [Asset]
    - **Credit**: User Supply ($+ \text{Interest Earned}$) [Liability] (calculated as $\text{Interest Accrued} \times (1 - \text{Reserve Factor})$)
    - **Credit**: Treasury Reserve ($+ \text{Interest Accrued} \times \text{Reserve Factor}$) [Equity]
*   **Events Emitted**: `InterestAccrued(asset, borrow_index, supply_index)`
*   **Post-execution Invariants**:
    - $\text{borrowIndex}_{t} \ge \text{borrowIndex}_{t-1}$

### G. Bad Debt Realization & Insurance Coverage
*   **Precondition**:
    - Liquidator seizes all remaining borrower collateral, but active borrower debt balance remains $> 0$.
    - Positions are fully closed.
*   **State Transition**:
    - Unrecoverable debt balance is written off by transferring assets from the Insurance Fund.
*   **Accounting Entries**:
    - **Debit**: Insurance Fund ($- \Delta \text{bad\_debt}$) [Equity]
    - **Credit**: User Debt ($- \Delta \text{bad\_debt}$) [Asset] (clearing user debt to 0)
*   **Events Emitted**: `BadDebtCovered(borrower, asset, amount)`
*   **Post-execution Invariants**:
    - User debt is fully cleared ($0$).
    - Insurance Fund $\ge 0$.
